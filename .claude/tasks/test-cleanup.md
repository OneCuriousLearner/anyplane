# 任务：清理不应存在或无意义的测试

审计 anyplane 仓库的全部测试（server/、scripts/、web/ 下的 `*.test.ts`）：

1. 先 `bun install`，然后在工作区根目录运行 `bun test` 确认基线全绿。
2. 找出以下三类问题测试：
   - 同义反复/假测试：不断言真实行为（如只测 mock 自身、assert true、快照式复制实现）；
   - 重复覆盖：与另一个测试断言完全等价、不增加任何行为保障；
   - 脆测试：钉死实现细节而非行为，重构时只会无意义地碎裂。
3. 对每一个判定给出书面理由，然后删除该测试，或重写为针对行为的有意义测试。
4. 每批改动后运行 `bun test`，必须保持全绿。
5. 按主题拆分 commit，消息里说明删除/重写每个测试的理由。

**保守原则**：拿不准的测试一律保留，并在 PR 描述中列出供人工判断；宁可少删也不错删。

## 判定纪律

- **重复覆盖必须举证**：以"重复"为由删除用例时，理由中必须指明覆盖同一行为的正本测试（文件路径 + 用例名），并确认它在当前基线全绿中真实运行；指不出正本的不得按重复删除。
- **漂移哨兵豁免**：刻意钉死协议/编码形状的测试不是脆测试——如 `server/src/backends/port.test.ts` 锁死 sessionKey 编码一一对应、协议基线类断言。它们是刻意设计的漂移哨兵，上游变更时碎裂正是其价值；不得按"脆"重写或删除，认为有问题的列入 PR 描述供人工判断。

## 跨平台与 CI 纪律

CI 在 ubuntu + windows 双平台各跑四道：`bun run typecheck` → `bun run lint` → `bun test` → `bun run build`。提交前必须本地跑过 typecheck 与 lint，只跑 `bun test` 不算绿。

重写用例时遵守顺序无关性：`bun test` 单进程跨文件共享模块实例，文件枚举顺序各平台不同——涉及全局单态的用例开头必须显式调用被测模块的复位口（仓库先例：`resetInboxSinkForTest`、`setStoreFileForTest`）；无复位口可用又不忍保留顺序依赖的，按保守原则保留原测试并列入 PR 描述。

## 执行环境

- 你在 anyplane 仓库的一个 git worktree 中工作，当前分支是脚本为此任务新建的（基于 origin/master）。
- 本项目仅使用 Bun（版本门槛见 AGENTS.md），绝不要用 npm / npx / yarn / pnpm。

## 提交与 PR 规范

- 按主题拆分 commit，消息清晰说明每个测试被删除/重写的理由（遵循仓库既有 commit 风格）。
- 精确实现任务要求——不要顺手改被测源码，也不要顺手补新测试（那是另一个任务的职责）。
- 全部完成后：`git push -u origin <当前分支>`，然后用 `gh pr create` 创建一个以 master 为 base 的 PR，正文逐项列出：删除/重写的测试 → 理由（重复类须含正本测试出处）→ 保留待人工判断的清单。
- 如果评估后认为没有值得清理的测试，不要强行制造改动；直接输出结论说明即可。
- 最后输出一段总结：处理清单与理由、commit 列表、PR 链接。
